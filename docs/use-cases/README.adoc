== Real-World Context

These use cases are derived from actual pain points in projects like:

* **spring-app-commons** - Multi-module Spring Boot project with complex Gradle conventions
* **gradle-convention** - Custom Gradle plugins for build standardization
* **General Gradle/Maven frustrations** - Slow builds, complex configuration, poor error messages

== Key Problems Solved

1. **Gradle's complexity** - 342 lines of Java for Error Prone configuration becomes YAML
2. **BuildSrc overhead** - Custom plugins become first-party or simple YAML
3. **Git hook performance** - `klx tool` starts instantly vs Gradle JVM warmup
4. **Configuration sharing** - Layered YAML files vs Maven/Gradle plugin publishing
5. **Reproducibility** - Mandatory lock files, immutable versions, supply chain verification

== Document Format

Each use case follows the link:https://en.wikipedia.org/wiki/Use_case#Cockburn_style[Cockburn format]:

* **Metadata** - Actor, scope, level, trigger
* **Stakeholders** - Who cares and what they want
* **Preconditions** - What must be true before
* **Postconditions** - What guarantees after
* **Main Success Scenario** - Happy path with numbered steps
* **Extensions** - Alternative flows and failures
* **Technology Variations** - Different ways to achieve goal
* **Special Requirements** - Constraints and quality attributes
